# Button and palette feedback review

Reviewed September 9, 2026 (UTC), against working-tree changes based on `eb5468db31a80243d1533d80db8575e35d530e98`. This is a scoped repair of the existing Figma source file, not a release audit or publication receipt. [Measured evidence](2026-09-09-feedback.json).

## Button cause and correction

The source gave secondary/filter variants a 1px border while primary/destructive/ghost variants had none, despite identical padding. At the 20px reference root, medium buttons were 45px high when filled and 47px when outlined. The same label measured 165px and 167px wide in Figma. `box-sizing: border-box` does not normalize intrinsically sized elements without a fixed dimension.

This asymmetry exists in the initial package commit `4d7c902` (April 10), before the Figma migration. That commit says the components were extracted from `ai-created-nextjs` and includes a Claude co-author; this establishes recorded AI involvement, not who authored the particular sizing decision or whether it originated upstream. The September 4 Figma-kit commit explicitly documented the existing 45/47px and 55/57px split.

`src/components/Button.tsx` now reserves the same border for every variant. The component's visual and construction contracts were corrected and generated artifacts regenerated. The 168 existing variants in [Button](https://www.figma.com/design/JArZlZoEHCZh5SdZ9FFOMA/AI-Created-UI?node-id=29-209) retain their IDs and editable properties. Filled and ghost text buttons grow by 2px in width and height; outlined dimensions and fixed icon targets are preserved.

| Size | Outer height at 20px root |
| --- | --- |
| Inline | 27px |
| Small / medium | 47px |
| Large / extra large | 57px |
| Icon | 55px square |

All variants and states match those dimensions with identical content. Existing overridden instances retained their labels and icon choices. A temporary instance verified primary/secondary parity after switching every size while preserving a custom label and leading icon. All 42 focus rings now use stretch constraints with exact 3px offsets so resizing does not scale the gap. The temporary test instance was removed.

Visual review covered [dark states](https://www.figma.com/design/JArZlZoEHCZh5SdZ9FFOMA/AI-Created-UI?node-id=104-87) and [light states](https://www.figma.com/design/JArZlZoEHCZh5SdZ9FFOMA/AI-Created-UI?node-id=104-596). Browser coverage checks all seven variants and six sizes at 16px and 20px roots, both themes, desktop/mobile, disabled, hover, keyboard focus and full width. Existing tests retain native activation and accessibility coverage. No loading, error, offline or permission behavior was added to Button.

## Palette presentation

The original reference board mixed unrelated families, wrapped long CSS expressions, and left near-black swatches indistinguishable from the canvas. The source values predate the Figma migration and are intentionally sparse, role-driven families.

The original board is now [Core & feedback colors](https://www.figma.com/design/JArZlZoEHCZh5SdZ9FFOMA/AI-Created-UI?node-id=15-2), with seven named groups and 30 swatches. The 54 accent swatches moved into [Nine accent families](https://www.figma.com/design/JArZlZoEHCZh5SdZ9FFOMA/AI-Created-UI?node-id=185-2), with aligned shade columns. Existing swatch IDs, exact source-token layer names and variable bindings were retained. Labels now show shade and hex value in the shared Code/sm style. Semantic strokes make very dark and light swatches visible in either theme.

Both boards were inspected in dark and light, then restored to dark. All 84 unique swatches were compared programmatically with `styles/tokens.css`; no token values changed. Labels fit their containers and retain the system's Space Grotesk, Instrument Serif and SF Mono fonts. The governing contract is the principal foundations reference → semantic → component hierarchy. No product-page archetype applies to these component and documentation repairs.
